# MemoLang — Data Model

PostgreSQL 18, accessed through `database/sql` with the pgx driver. The source of truth is `internal/db/migrations/`; this page explains it.

## Tables

```
users                 — id, email, password_hash (bcrypt; '' reserved for future
                        OAuth-only accounts), display_name (optional; User.Name()
                        falls back to email), created_at, email_verified_at
                        (NULL = unverified, can't log in)
user_sessions         — token_hash (PK, hex sha256 of the cookie value), user_id → users,
                        created_at, expires_at (login sessions; distinct from study_sessions)
email_codes           — (user_id, purpose) PK, code_hash, new_email (set iff
                        purpose = 'change_email'), attempts, created_at, expires_at;
                        purpose ∈ verify | reset | change_email
auth_attempts         — id, kind, key, created_at (rate-limit events, counted per window)
decks                 — id, user_id → users (owner), name, mode ('srs' | 'linear'), created_at
cards                 — id, deck_id → decks, front, back, example, tags,
                        SM-2 fields (interval_days, ease, repetitions, due_date),
                        created_at; UNIQUE (deck_id, front)
study_sessions        — id, deck_id → decks, quiz_mode, card_queue (JSONB int array),
                        position, correct, total, started_at, ended_at
session_answers       — id, session_id → study_sessions, card_id → cards, correct,
                        given, answered_at (backs the feedback and summary screens)
settings              — (user_id, key) PK, value, updated_at; per-user key/value,
                        unused since the llm.* keys moved to llm_providers
llm_providers         — id, user_id → users, name, preset, base_url, model, api_key,
                        active, disable_thinking, created_at
conversations         — id, user_id → users, kind ('tutor' | 'deck_builder'),
                        card_id → cards (set iff kind = 'tutor'), created_at
conversation_messages — id, conversation_id → conversations, role ('user' | 'assistant'),
                        content, status ('done' | 'generating' | 'error'), created_at
```

Every deck is owned by a user; cards, study sessions and answers inherit ownership through `deck_id`, so `decks.user_id` is the only owner column on that branch. Foreign keys are `ON DELETE CASCADE`, so `DeleteUser` removes everything the account owns.

Secrets are stored hashed: `user_sessions.token_hash` and `email_codes.code_hash` hold `hex(sha256(value))` (`models.hashToken`); the raw value lives only in the cookie or the email. See `docs/plans/verified-auth-plan.md`.

Constraints the database enforces:

- Email uniqueness: unique index on `lower(email)` (no citext); emails are also stored lowercased (`models.NormalizeEmail`).
- At most one active LLM provider per user: partial unique index on `llm_providers(user_id) WHERE active`. Switching is `ActivateLLMProvider`, one transaction.
- One tutor conversation per user per card, one deck-builder conversation per user: partial unique indexes on `conversations`.

## Conventions

- Ids are `BIGINT GENERATED BY DEFAULT AS IDENTITY` (not `ALWAYS`, so fixtures and restores can set one).
- Timestamps are `TIMESTAMPTZ`; `due_date` is `DATE`; flags are `BOOLEAN`.
- The SM-2 interval column is `interval_days` — `INTERVAL` is a Postgres keyword.
- Placeholders are `$1, $2, …`.
- A duplicate is detected by SQLSTATE `23505` (`isUniqueViolation`), never by error text.
- Scoped `UPDATE`/`DELETE` go through `requireRowAffected`, so a zero-row write is `sql.ErrNoRows`.

## Migrations

`db.Open(DATABASE_URL)` runs `internal/db/migrations/NNNN_*.sql` in order, recording each in `schema_migrations` (`internal/db/migrate.go`).

- To change the schema, add the next numbered file and a `{version, file}` entry to `migrations`. **Never edit a shipped migration.**
- Postgres DDL is transactional, so each migration is one transaction.
- A Postgres advisory lock serialises concurrent starts, so several pods never apply the same migration twice.
- `0001_baseline.sql` is the schema the eight SQLite migrations (in git history) had reached; SQLite data was not carried over.

## Running locally and in tests

- `task dev` builds with `-tags dev`, which compiles in `internal/devdb` (embedded Postgres in `./.pgdata`) when `DATABASE_URL` is unset. The production binary does not contain it, so a missing `DATABASE_URL` there is a startup error. `task db:reset` wipes `./.pgdata`.
- Every package that uses the database has `func TestMain(m *testing.M) { pgtest.Main(m) }`, which runs an embedded Postgres (binaries downloaded once and cached; no Docker).
- `testdb.New(t)` gives each test a fresh migrated database copied from a template (`CREATE DATABASE … TEMPLATE`).
